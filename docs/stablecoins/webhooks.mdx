Stablecoin activity reaches your server as three events, delivered as HTTPS POSTs to the webhook URL configured on your dashboard:

| Event | Fires when | Act on it |
|---|---|---|
| `deposit.success` | An incoming deposit passed its confirmation threshold and the balance was credited. | Credit the user. |
| `transfer.success` | An outbound send confirmed on-chain. | Mark the transfer delivered. |
| `transfer.failed` | An outbound send was rejected, reverted, or timed out; held funds returned to your balance. | Unlock the funds in your ledger, surface the failure. |

Never credit or debit on anything earlier than these events. A transaction visible on-chain is not yet final, and an accepted API call is not yet a completed send.

## Verify every delivery

Each request carries an `x-bitnob-signature` header: HMAC-SHA512 of the raw body, keyed with your webhook secret. Verify against the raw bytes, compare in constant time, and reject mismatches.

```javascript
const crypto = require('crypto');
const express = require('express');
const app = express();

const secret = process.env.BITNOB_WEBHOOK_SECRET;

app.post('/webhook', express.raw({ type: 'application/json' }), (req, res) => {
  const signature = req.headers['x-bitnob-signature'] || '';
  const expected = crypto.createHmac('sha512', secret).update(req.body).digest('hex');

  const valid =
    expected.length === signature.length &&
    crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(signature));

  if (!valid) return res.status(400).send('Invalid signature');

  const event = JSON.parse(req.body.toString('utf-8'));
  // route on event.event, de-duplicate on event.event_id
  res.status(200).send();
});
```

Reference implementations and the published [Source IPs](/api-reference/addresses/webhooks#source-ips) are under [Verifying events](/api-reference/addresses/webhooks#verifying-events). Treat any IP allowlist as a second layer; the signature is the check that counts.

## The payloads

## Delivery semantics

- Return `200` quickly; non-200 responses are retried 3 times after the first failure.
- Retries mean duplicates: de-duplicate on `event_id`.
- Endpoints must be HTTPS and respond within 5 seconds; process asynchronously.
- Keep the backstop: sweep [List transactions](/api-reference/transactions/list-transactions) on a schedule so a missed delivery never becomes a wrong balance. [Get transaction by id](/api-reference/transactions/get-transaction-by-id) resolves a single reference.

While developing locally, tunnel with a tool like [ngrok](https://ngrok.com/) and point your test-environment webhook URL at it; never a production one.
