The Trade Status & History endpoints allow you to:

- Fetch a single trade by ID or reference
- List crypto-pair trades across your account
- Monitor conversion volumes, timestamps, and trade outcomes
- Power your ledger, dashboards, and audit flows

## Retrieve one order

Full reference: [Get Order By ID](/api-reference/trading/get-order-by-id-or-reference).

```bash
GET /api/trading/orders/:id
```

### Path parameter

| Parameter | Type | Required | Description |
|---|---|---|---|
| id | string | Yes | Order ID, or your `reference` for a crypto-pair order |

Use the order `id` for any pair. Lookup by your own `reference` works for crypto-pair orders only; an NGN reference returns `400` `invalid id`.

### Example request

```bash
curl --location 'https://api.bitnob.com/api/trading/orders/4ac59dd0-3c25-43c7-8e51-2ed020149e1b' \
--header 'Content-Type: application/json' \
--header 'x-auth-client: CLIENT_ID' \
--header 'x-auth-timestamp: TIMESTAMP' \
--header 'x-auth-nonce: NONCE' \
--header 'x-auth-signature: SIGNATURE'
```

## List orders

Full reference: [Get Orders](/api-reference/trading/list-orders). The list returns crypto-pair orders only. NGN trades aren't included, so fetch those one at a time by ID with [Get Order By ID](/api-reference/trading/get-order-by-id-or-reference).

```bash
GET /api/trading/orders
```

### Query parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| status | string | No | Filter by order status: `pending`, `filled`, `rejected`, or `cancelled`. |
| limit | integer | No | Number of orders per page. |

The response carries `total_count`, `has_more`, and `next_cursor` alongside the `orders` array.

### Example request

```bash
curl --location 'https://api.bitnob.com/api/trading/orders' \
--header 'Content-Type: application/json' \
--header 'x-auth-client: CLIENT_ID' \
--header 'x-auth-timestamp: TIMESTAMP' \
--header 'x-auth-nonce: NONCE' \
--header 'x-auth-signature: SIGNATURE'
```

### Example response

| Field | Meaning |
|---|---|
| `total_count` | Number of orders that match, as a string. |
| `has_more` | `true` when there are more orders after this page. |
| `next_cursor` | Cursor for the next page. Empty when `has_more` is `false`. |

## Order statuses

| Status | Meaning |
|---|---|
| `pending` | Accepted, not yet filled. |
| `filled` | Executed completely. The terminal success state. |
| `rejected` | Not executed. `filled_quantity` stays `0`. |
| `cancelled` | Cancelled before fill via [Cancel order](/api-reference/trading/cancel-order). |

## What to build on it

Powering ledger UIs or admin dashboards with completed trade data

Matching internal accounting and reconciliation jobs

Investigating failed trades by reference ID via [Get Order By ID](/api-reference/trading/get-order-by-id-or-reference)

Generating usage-based analytics or reporting
