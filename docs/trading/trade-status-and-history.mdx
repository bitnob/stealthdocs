The Trade Status & History endpoints allow you to:

- Fetch a single trade by ID or reference
- List all trades across your account (optionally filtered)
- Monitor conversion volumes, timestamps, and trade outcomes
- Power your ledger, dashboards, and audit flows

## Retrieve one order

Full reference: [Get Order By ID](/api-reference/trading/get-order-by-id-or-reference).

```bash
GET /api/trading/orders/:id
```

### Path parameter

| Parameter | Type | Required | Description |
|---|---|---|---|
| id | string | Yes | Trade ID or reference ID |

You can use either a Bitnob-generated tradeId or your own reference to fetch the trade.

### Example request

```bash
curl --location 'https://api.bitnob.com/api/trading/orders/4ac59dd0-3c25-43c7-8e51-2ed020149e1b' \
--header 'Content-Type: application/json' \
--header 'x-auth-client: CLIENT_ID' \
--header 'x-auth-timestamp: TIMESTAMP' \
--header 'x-auth-nonce: NONCE' \
--header 'x-auth-signature: SIGNATURE'
```

## List orders

Full reference, including the supported filters: [Get Orders](/api-reference/trading/list-orders).

```bash
GET /api/trading/orders
```

### Query parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| from | string | No | Filter by source asset (usdt, usdc, btc, or ngn) |
| to | string | No | Filter by target asset (usdt, usdc, btc, or ngn) |
| status | string | No | Filter by status (completed, failed) |
| startDate | string | No | ISO8601 format: return trades after this date |
| endDate | string | No | ISO8601 format: return trades before this date |
| limit | integer | No | Number of trades per page (default 20, max 100) |
| cursor | string | No | Cursor for pagination |

### Example request

```bash
curl --location 'https://api.bitnob.com/api/trading/orders' \
--header 'Content-Type: application/json' \
--header 'x-auth-client: CLIENT_ID' \
--header 'x-auth-timestamp: TIMESTAMP' \
--header 'x-auth-nonce: NONCE' \
--header 'x-auth-signature: SIGNATURE'
```

## Order statuses

| Status | Meaning |
|---|---|
| `pending` | Accepted, not yet filled. |
| `filled` | Executed completely. The terminal success state. |
| `cancelled` | Cancelled before fill via [Cancel order](/api-reference/trading/cancel-order). |

## What to build on it

Powering ledger UIs or admin dashboards with completed trade data

Matching internal accounting and reconciliation jobs

Investigating failed trades by reference ID via [Get Order By ID](/api-reference/trading/get-order-by-id-or-reference)

Generating usage-based analytics or reporting
