## 1. Overview

Ghana is one of Africa’s strongest mobile money ecosystems.

While traditional bank accounts exist and are growing, mobile money (especially MTN Mobile Money, also known as MTN MoMo ) dominates daily payments, merchant transactions, and personal fund transfers.

For payout products, the practical reality is:

- **Two rails:** bank transfer and mobile money. Most retail payouts go to mobile money.
- **Mobile money covers MTN MoMo, Telecel Cash and AirtelTigo Money.** Send the `network` that matches the recipient's number.
- Read the destination types and their fields from [Country requirements](/api-reference/payouts/country-requirements) at runtime rather than hardcoding them.

## 2. Settlement methods available

| Method | Description |
|---|---|
| Bank transfer | Payouts to Ghanaian bank accounts. Take the `bank_code` from [Get banks](/api-reference/payouts/banks-by-country). |
| Mobile money | Payouts to MTN MoMo, Telecel Cash and AirtelTigo Money wallets, identified by phone number. Send `network` as `mtn`, `vodafone` (Telecel) or `airtel` (AirtelTigo). |

<Note>
  Over 90% of retail and micro-merchant payouts favor Mobile Money channels, especially MTN.
</Note>

## 3. Beneficiary validation standards

How you validate a GHS beneficiary depends on the rail.

- **Mobile money:** for MTN numbers, confirm the wallet with [Account lookup](/api-reference/payouts/account-lookup). Pass `country=GH`, `type=mobile_money`, `MTN` as the `bank_code` (case doesn't matter), and the phone number as the `account_number`, either as `233XXXXXXXXX` or `0XXXXXXXXX`. Leave out `type=mobile_money` and the lookup fails with `400`. For Telecel Cash and AirtelTigo Money numbers, have your user confirm the account name before you finalize.
- **Bank account:** Account lookup doesn't support Ghana bank accounts yet. A lookup with a Ghana bank code returns `400` `VALIDATION_ERROR`. Take the `bank_code` from [Get banks](/api-reference/payouts/banks-by-country) (for example `GH190100` for Stanbic Bank, `GH040100` for GCB Bank Ltd) and collect the `account_name` from your user.

<Warning>
  Because a Ghana bank account name can't be checked up front, a wrong account number is only caught when the bank rejects the transfer. Have your user confirm the account number and name before you finalize.
</Warning>

| Type | Validation Process |
|---|---|
| Mobile Money Wallets | Validate the phone number format and work out the network from its prefix. Resolve MTN wallet names with Account lookup. |
| Bank Accounts | Check the `bank_code` against Get banks for GH. Check the account number is digits only and matches the length your user's bank uses. Account lookup isn't available, so have the user confirm the account name. |

 Best Practices for Mobile Money Validation

 Work out the network from the number's prefix and send the matching `network`.

 Normalize mobile numbers (e.g., remove leading 0, standardize to international format if needed, e.g., 23324xxxxxxx).

 Check wallet registration status if provider API allows.

 Check wallet tier restrictions (if available) for maximum transaction limits.

### 4. Mobile money wallet tiering and transaction limits

Mobile money accounts in Ghana are often tiered based on KYC. The corridor min/max Bitnob enforces comes from [Get Limits](/api-reference/payouts/payout-limits):

| Wallet tier | Limits |
|---|---|
| Tier 0 (Basic Registration) | Low daily transaction limit (~GHS 1,000) and low wallet balance cap. |
| Tier 1 (Full KYC with ID) | Higher daily limits (~GHS 5,000–10,000) and wallet caps. |
| Tier 2 (Business Wallets) | Even higher limits, used for SMEs and merchants. |

 Impact on Payouts:

If a payout exceeds the recipient's wallet tier limit, the transaction will fail immediately or be auto-reversed to sender.

Some providers may hold funds temporarily pending user wallet upgrade (rare but possible).

 Product Requirement:

 Educate users about wallet limits when setting up high-value payouts.

 Monitor reversals dynamically and surface payout status changes to users immediately.

## Ghana mobile money network and prefixes

GHS mobile money payouts go to MTN MoMo, Telecel Cash and AirtelTigo Money. Send the `network` that matches the recipient's number.

MTN is the largest mobile network operator in Ghana and the dominant mobile money provider, with over 90% of the wallet market.

| Network | `network` value | Prefixes |
|---|---|---|
| MTN MoMo | `mtn` | 024, 054 (original ranges); 025, 055, 059 (added later) |
| Telecel Cash (formerly Vodafone Cash) | `vodafone` | 020, 050 |
| AirtelTigo Money | `airtel` | 026, 056 |

Mobile money wallets are tied to these phone numbers.

## Validation best practices for Ghana mobile money

| Step | Best Practice |
|---|---|
| Phone format | Normalize numbers to one format. Example: 024xxxxxxx → 23324xxxxxxx. |
| Carrier check | Work out the network from the prefix and send the matching `network`. |
| Wallet status | Resolve the wallet with Account lookup before you pay out. |
| Amount limits | Respect wallet tier limits, especially for Tier 0 and Tier 1 users. |

## Common failure modes

| Failure mode | Description | Response |
|---|---|---|
| Wrong network | The `network` sent doesn't match the recipient's number, for example `mtn` for a Telecel Cash number. | Work out the network from the prefix before paying out. |
| Invalid mobile number | Wrong length or format. Ghanaian mobile numbers are 10 digits nationally (0XXXXXXXXX). | Normalize to one format and validate the prefix before submitting. |
| Inactive or unregistered wallet | The mobile money account is closed, dormant, or never completed registration. | Resolve the account name with Account lookup before paying. Fail fast and refund rather than retrying blindly. |
| Limit exceeded | Payout above the recipient's daily limit. | Split large payouts into compliant amounts. |
| Invalid bank account or bank code | The account number doesn't exist at the bank, or the `bank_code` doesn't match the recipient's bank. | Take bank codes from Get banks rather than hardcoding them. Because Account lookup isn't available for Ghana bank accounts, have the user confirm the details before finalizing. |

## Operational best practices

| Area | Recommendation |
|---|---|
| Network detection | Work out the network from the phone number prefix and send the matching `network` value. |
| Number normalization | Store one canonical format (for example 23324xxxxxxx), so 024xxxxxxx, +233 24 xxx xxxx and 23324xxxxxxx all resolve to the same wallet. |
| Validation | For MTN numbers, resolve the beneficiary name with Account lookup before releasing funds, passing `MTN` as the `bank_code`. For Telecel Cash, AirtelTigo Money and bank accounts, have the user confirm the account name. |
| Bank payouts | Take bank codes from Get banks rather than hardcoding them, and show the user the account name and number to confirm before you finalize. Set expectations that bank payouts take 1 to 10 minutes. |

## Closing note

For mobile money, sending the right `network` for the number is the critical first step to fast, successful payouts in Ghana. For bank payouts, the equivalent is confirming the bank code and account details with your user, since they can't be looked up.

Paying out with the wrong network or a wrong number can lead to:

- Delayed refunds,
- Auto-reversals,
- User frustration,
- Increased operational costs.
