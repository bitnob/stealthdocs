title: "Issue your first card"
description: "Take one card through its whole life: verify the cardholder, create and fund the card, handle spends and refunds, then freeze or terminate it."
---

In this tutorial you take one card through its whole life: verify the cardholder, create the card, fund it, see a transaction land, handle a refund, and shut the card down. By the end you have every integration point a production card programme needs.

## Prerequisites

- Your API credentials and a working signing helper; see [Authentication](/api-reference/authentication/authentication).
- A reachable webhook endpoint that [verifies signatures](/docs/card-issuing/webhook-payloads#verifying-events).
- Enough in your company balance to cover the card's opening amount plus fees. The \$2.00 card in this tutorial takes \$4.00: the \$2.00 load, a \$1.00 top-up fee, and a \$1.00 creation fee. See [What creating a card costs](/docs/card-issuing/card-issuance#what-creating-a-card-costs).

Amounts throughout are integers in micro-units: 1 USD = 1,000,000, so `2000000` is \$2.00.

<Steps>
  <Step title="Verify the cardholder">
    Every card starts with a verified cardholder. Submit their identity details to [Card KYC](/api-reference/cards/card-kyc). The response returns the `customer_id` you pass to Create card. Identity details are captured here, so you don't send them again when you create the card.

    ```http
    POST /api/cards/kyc
    ```

    ```json
    {
      "customer": {
        "customer_type": "individual",
        "first_name": "Amaka",
        "last_name": "Eze",
        "date_of_birth": "1992-05-14",
        "id_type": "bvn",
        "id_number": "22415315108",
        "email": "amaka.eze.6788f4@example.com",
        "phone_number": "8179251297",
        "dial_code": "+234",
        "line1": "12 Admiralty Way",
        "city": "Lagos",
        "state": "Lagos",
        "postal_code": "101233",
        "country": "NGA"
      },
      "occupation": "software_engineer",
      "employment_status": "employed",
      "account_purpose": "online subscriptions",
      "annual_salary": "12000000",
      "expected_monthly_volume": "500000",
      "place_of_birth": "Enugu",
      "terms_of_service_accepted": true
    }
    ```

    With a BVN, approval can come back in the same response:

    ```json
    {
      "success": true,
      "message": "Card KYC initiated successfully",
      "data": {
        "customer_id": "01a14942-c667-783d-8e42-9d9d4828bc60",
        "status": "approved",
        "completion_link": "",
        "email": "amaka.eze.6788f4@example.com",
        "first_name": "Amaka",
        "last_name": "Eze",
        "normalized_status": "approved"
      },
      "timestamp": "2026-10-17T09:47:55.452509813Z"
    }
    ```

    <Note>
      KYC can be asynchronous. Wait until the customer is approved before you issue a card. If `status` comes back pending, `completion_link` holds a URL the cardholder must finish, and the outcome arrives on the `virtualcard.user.kyc.complete` or `virtualcard.user.kyc.failed` webhook.
    </Note>

    If a customer with that `id_number` already exists under a different email, Card KYC returns `400` with that customer's ID in the `detail`. Resubmit with `customer_id` in place of the `customer` object to verify the existing customer.

    Store the `customer_id`. It's the input to the next step.
  </Step>
  <Step title="Create the card">
    Issue the card against the approved `customer_id`. `name` is optional and defaults to the customer's name. Full schema: [Create card](/api-reference/cards/create-card-embedded-customer).

    ```http
    POST /api/cards
    ```

    ```json
    {
      "card_type": "virtual",
      "currency": "USD",
      "amount": 2000000,
      "card_brand": "visa",
      "customer_id": "01a14942-c667-783d-8e42-9d9d4828bc60",
      "reference": "CARD_CREATE_7e685abc-40bc-4ca2-b7aa-209fad4777d6"
    }
    ```

    `webhook_url` and `contactless_payment` are optional; see [Create card](/api-reference/cards/create-card-embedded-customer) for every field.

    The response returns the card in status `pending`, with no card number yet:

    ```json
    {

      "message": "Card created successfully",
      "data": {
        "card": {
          "id": "01a14943-44cf-7b97-832e-5a70803c54b9",
          "company_id": "b1ebb43e-068f-4b6a-bbab-5c3027bc1510",
          "customer_id": "01a14942-c667-783d-8e42-9d9d4828bc60",
          "card_type": "virtual",
          "status": "pending",
          "created_status": "processing",
          "card_brand": "visa",
          "name": "Amaka Eze",
          "preferred_name": "Amaka Eze",
          "first_six_digit": "000000",
          "masked_pan": "000000******",
          "balance_amount": "0",
          "balance_currency": "USD",
          "display_amount": 0,
          "contactless_payment": false,
          "card_limits": {},
          "reference": "CARD_CREATE_7e685abc-40bc-4ca2-b7aa-209fad4777d6",
          "card_program": "prepaid",
          "nickname": "",
          "business_spend": null,
          "available_actions": [],
          "balance_breakdown": null,
          "user_metadata": "{}",
          "billing_address": {
            "line1": "3401 N. Miami, Ave. Ste 230",
            "line2": "",
            "city": "Miami",
            "state": "Florida",
            "postal_code": "33127",
            "country": "United States"
          },
          "created_by": "b1ebb43e-068f-4b6a-bbab-5c3027bc1510",
          "created_at": "2026-10-17T09:48:27Z",
          "updated_at": "2026-10-17T09:48:27Z"
        }
      },
    ```

    The opening `amount` and both fees are taken from your company balance at this point. If it can't cover them, the call fails with `400` and `extensions.error_code` `COMPANY_INSUFFICIENT_BALANCE`.

    Store the card `id`. Every later call uses it.
  </Step>

  <Step title="Wait for the activation webhook">
    The issuer confirms creation with `virtualcard.created.completed`:

    ```json
    {
      "eventId": "7f3a9c2b-4d1e-4f5a-8b9c-1d2e3f4a5b6c",
      "companyId": "6fbce816-de98-45e5-882f-70fb379d0a0c",
      "event": "virtualcard.created.completed",
      "data": {
        "id": "80dd9cc5-82ba-4395-8c8e-4567f1e90ab4",
        "status": "active",
        "reference": "CARD_CREATE_A4FAC6DF5727",
        "createdStatus": "completed",
        "reissue": false
      }
    }
    ```

    This is the signal to show the card in your UI. Fetch the PAN, CVV, and expiry with [Get secure card details](/api-reference/cards/get-secure-card-details), display them once, and do not store the CVV. If creation fails you get `virtualcard.created.failed` with a `reason`.

    You can also check with [Get card](/api-reference/cards/get-card). Once the card is `active`, it shows the last four digits and the opening balance:

    ```json
    {
      "success": true,
      "message": "Card retrieved successfully",
      "data": {
        "card": {
          "id": "01a14943-44cf-7b97-832e-5a70803c54b9",
          "status": "active",
          "created_status": "completed",
          "last_four_digit": "7725",
          "masked_pan": "000000******7725",
          "balance_amount": "2000000",
          "display_amount": 2,
          "available_actions": [
            "FUND",
            "WITHDRAW",
            "FREEZE",
            "UPDATE_LIMITS",
            "TERMINATE"
          ]
        }
      }
    }
    ```
  </Step>

  <Step title="Fund the card">
    Load USD from your balance with [Fund or withdraw balance](/api-reference/cards/fund-or-withdraw-balance). `type: "fund"` credits the card; `type: "withdraw"` moves value back.

    ```http
    POST /api/cards/{cardId}/balance
    ```

    ```json
    {
      "amount": 2000000,
      "reference": "FUND_TYU039847383",
      "type": "fund"
    }
    ```

    `reference` is your idempotency key: retrying with the same reference returns the original transaction instead of double-funding. Confirmation arrives as `virtualcard.topup.completed`; a failure, for example insufficient balance or a frozen card, arrives as `virtualcard.topup.failed`. Funding constraints and fees are in [Fund a card](/docs/card-issuing/card-funding).
  </Step>

  <Step title="Handle a spend">
    When the cardholder pays a merchant, the settled charge reaches you as `virtualcard.transaction.debit`:

    ```json
    {
      "eventId": "06cd8fab-da0b-4c4d-87e8-0a1b2c3d4e5f",
      "companyId": "c16a147e-119f-4de4-88c0-b14d908f9727",
      "event": "virtualcard.transaction.debit",
      "data": {
        "cardId": "8a1fcb84-28cb-4d6e-a6c3-a19dbac4789b",
        "id": "tx_debit_a1b2c3d4e5f6",
        "amount": 10000000,
        "displayAmount": 10.0,
        "currency": "usd",
        "transactionType": "settlement",
        "reference": "spend_txn_001",
        "narrative": "SPOTIFY",
        "timestamp": "2026-05-16T14:22:10Z",
        "status": "completed",
        "merchantName": "spotify",
        "merchantMcc": "5815",
        "merchantCountry": "se"
      }
    }
    ```

    Branch on `event` first, then on `transactionType`; several events share a name across pending and settled states. The full catalogue is on [Webhook events](/docs/card-issuing/webhooks). The same activity is queryable with [List card transactions](/api-reference/cards/list-card-transactions-by-card).
  </Step>

  <Step title="Handle a refund or reversal">
    Merchants return money two ways, and both arrive as webhooks: `virtualcard.transaction.refund` after settlement, `virtualcard.transaction.reversed` when an authorisation is cancelled before settlement. Credit your user's view of the balance from these events; correlate to the original spend via `reference`.
  </Step>

  <Step title="Freeze, unfreeze, or terminate">
    Give users a freeze button, and keep termination for endings:

    ```http
    POST /api/cards/{cardId}/status
    { "status": "frozen" }     # or "active" to unfreeze

    DELETE /api/cards/{cardId}
    { "reason": "Card no longer needed" }
    ```

    Freezing blocks new authorisations immediately and is reversible via [Freeze or unfreeze](/api-reference/cards/freeze-or-unfreeze). [Terminate](/api-reference/cards/terminate-card) is permanent, sweeps the remaining balance back to your wallet, and cannot be called within 24 hours of creation. Details and the automatic transitions are in [Freeze, unfreeze, or terminate a card](/docs/card-issuing/card-status-management).
  </Step>
</Steps>

## Production checklist

- Idempotency keys on card creation and every top-up.
- Webhook handler verifies the signature, de-duplicates on `eventId`, and returns `200` fast.
- Card status tracked in your database and reflected in your UI.
- CVV never stored; `masked_pan` shown only after user authentication.
- Decline handling wired: repeated declines carry fees and can terminate the card. See [Fees and decline rules](/docs/card-issuing/card-fees).
